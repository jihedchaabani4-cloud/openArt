## 4. Answers to Questions

### Q1: Where does the payload produced by `serialize` go?
1. Produced in `PromptBarPlatform.jsx:254` via `store.serialize()`.
2. Passed to `onGenerate(requestPayload)` in `assets/page.js:366` or `collection/[collectionId]/page.js:476`.
3. Handled in `handleGenerate(request)` (`assets/page.js:76-103`), constructing `payload = { model, prompt, project_id, folder_id, parameters, references, elements, characters }`.
4. Dispatched via `runGenerate({ payload, isVideo })` in `useGenerateMutation.js:13-19`.
5. Sent via HTTP POST to:
   - `/api/video/generated` (if video model)
   - `/api/images/generated` (if image model)

### Q2: Backend validator/controller behavior
- **Undeclared parameters**: The backend strictly **REJECTS** unknown/undeclared parameters! `apiOpenArt/src/models/schema/schemaValidator.js:159` throws `UnknownParameterError(key)` if `rawInput` contains a parameter not declared in the model's manifest.
- **`references`, `elements`, `characters`**:
  - `references`: Optional array (`references = []`), validated for ownership only (`assertOwnsAny`).
  - `elements`: NOT required, NOT validated, ignored by generation controllers.
  - `characters`: NOT required, NOT validated, ignored by generation controllers.
- **Where are `input_image` / `images` read?**
  - Read strictly from `inputs.parameters` in `imageGenerationNode.js` and `videoGenerationNode.js`. They are NOT read from `references`.

### Q3: Fixture Models Payload Analysis

#### (a) Frames Model (`seedance_2_5`)
- **Frontend sends**:

- **Frontend sends**:

- **Undeclared keys needed**: NONE.

### Q4: Verdict for Decision PB-D-12
**Verdict: A) "emit only declared parameters" is 100% SAFE and MANDATORY.**
- The backend's `schemaValidator.js` actively throws `UnknownParameterError` if any undeclared key is present in `parameters`.
- Today's frontend behavior (PB-K2: leaking undeclared media parameters) is dangerous and causes runtime 400 errors if an undeclared media key is left in `parameterValues`.
- Emitting only parameters declared by the model's manifest completely protects against `UnknownParameterError` and matches backend expectations.

## 5. Verdict
**CONFIRMED (SAFE)**: Emitting strictly declared parameters conforms to the backend contract. `references`, `elements`, and `characters` remain at root for contract and telemetry compliance.

## 6. Risks
- If a frontend template needs to pass a new parameter not yet declared in the backend model manifest (e.g. experimental flag), it will be rejected by the backend unless added to the backend model's `canonicalInputs` schema.
