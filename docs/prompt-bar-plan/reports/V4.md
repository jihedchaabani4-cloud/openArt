## 4. Answers to Questions

### Q1: Step-by-step trace of actions and stores
1. **`animateMedia`** (`mediaReferenceService.js:389-486`):
   - Reads `store.getState()`: `modelsMap`, `selectedModelId`, `parameterValues`, `prompt`.
   - Calls `setActiveMode("video")` (line 415).
   - Calls `setActiveSubMode("frames")` (line 418).
   - Cleans old references: calls `clearMediaReferences()` or deletes `images`/`reference_images` and cleans prompt tags via `cleanTagsForAsset` (lines 422-449).
   - Validates model eligibility; if current model is not a video model with `input_image`, calls `selectModel(targetModel.id)` (lines 452-469).
   - Resolves `startKey` (defaults to `"input_image"`) and `endKey` (defaults to `"last_frame"`).
   - Writes start frame: `setParameter(startKey, asset)` (line 480).
   - Clears end frame: `setParameter(endKey, undefined)` (line 482).
   - Returns `true`.
2. **`addMediaToPrompt`** (`mediaReferenceService.js:220-373`):
   - Reads `store.getState()`: `activeMode`, `activeSubMode`, `selectedModelId`, `modelsMap`, `parameterValues`.
   - If asset is an entity (character/element): forces `setActiveMode("image")` and selects model with `maxRefs >= requiredCount` (lines 248-268).
   - If entity, calls `addCharacter(asset)` or `addElement(asset)` (lines 301-305).
   - If active composition has `"reference"` slot: appends to `parameterValues.images` array or sets single parameter (lines 307-332).
   - If active composition has `"start"`/`"end"` slots: fills Start frame if empty, else fills End frame, else overwrites Start frame (lines 334-360).
3. **`consumePendingPromptAction`** (`mediaReferenceService.js:47-60`):
   - Reads `sessionStorage.getItem("openart_pending_prompt_action")`.
   - Immediately calls `sessionStorage.removeItem("openart_pending_prompt_action")` and returns parsed JSON.
   - Handled in `PromptBarPlatform.jsx:168-181` inside `useEffect` on mount.
4. **`useMediaActions.js`**:
   - `handleReuseSettings` (lines 149-192):
     - Writes to `activeBarStore`: `setPrompt(effectivePrompt)`, `selectModel(modelName)`, `setParameter("ratio", ...)`, `setParameter("aspect_ratio", ...)`, `setActiveMode(...)`.
     - Writes to `usePromptStore`: `setGenerationMode`, `setPrompt`, `setModelId`, `setRatio`, `setReferenceImages`, `setQuality`, `setVideoResolution`, `setDuration`, `setMotion`, `setCount`.
     - Focuses editor via `document.querySelector(...)`.
   - `handleAnimate` (lines 205-236):
     - Calls `animateMedia({ media })`.
     - If returns false (bar unmounted on characters/collection page): calls `setPendingPromptAction({ type: "animate", media, projectId })` and redirects to `/cinema-studio/${projectId}/assets`.
     - If not an assets redirect: writes to `usePromptStore` (`setGenerationMode("keyframe")`, `clearReferences()`, `addReference(..., "start")`).
     - Focuses editor via `document.querySelector(...)`.

### Q2: Claim: "Animate works because the image already sits in input_image when mode switches"
- **Verdict: REFUTED** (VERIFIED).
- **Evidence**:
  - `mediaReferenceService.js:480` explicitly executes `setParameter(startKey, asset)`.
  - The mode transition happens on line 415; the explicit parameter write happens on line 480.
  - Animate does NOT rely on accidental carry-over or PB-K1. It explicitly assigns the asset to the start frame parameter.
  - **Plan impact**: Decision PB-D-03 (wiping all media parameters on mode/sub-mode change) will **NOT** break `animateMedia`, because `animateMedia` sets `setParameter(startKey, asset)` after initiating the mode transition.

### Q4: Pending Action Queue Lifecycle
- Stored in `sessionStorage["openart_pending_prompt_action"]`.
- Consumed once on initial mount of `PromptBarPlatform` via `useEffect` after `modelsMap` loads (`PromptBarPlatform.jsx:168-181`).
- Cleared immediately upon retrieval.
- **Can it be consumed twice?** No, key is deleted on read and `executedPendingRef.current = true` prevents re-runs.
- **Can it be lost?** Yes. If the user navigates away before `modelsMap` finishes loading, or if multiple actions are triggered rapidly in succession (only the latest survives in sessionStorage).

## 5. Verdict
**REFUTED**: Animate sets `input_image` itself via explicit `setParameter(startKey, asset)`. It does not depend on media persistence across mode transitions.

## 6. Risks
- Direct DOM query `document.querySelector('[contenteditable="true"]')` is fragile and bypasses React ref encapsulation.
- `setPendingPromptAction` holds only a single action object rather than an array; rapid consecutive actions overwrite each other.
