## Evidence (tag each: VERIFIED / INFERRED / NOT-RUN)
- VERIFIED: Stale `isGenerating: true` from a prior session or ungraceful reload is immediately reset on mount when `registry.isSubmitting(identity)` is false.
- VERIFIED: A submit genuinely in flight is NOT reset if another mount occurs for the same identity.
- VERIFIED: `endSubmit` with an unrecognized or expired token does nothing and does not reset `isGenerating` prematurely.
- VERIFIED: When `onGenerate` throws an exception, `finally` executes `endSubmit(token)` cleanly, ensuring `isGenerating` is reset to false.
- VERIFIED: `isGenerating` is omitted from `selectPersistable(state)` and never reaches serialized JSON in storage.
- VERIFIED: V5 Verdict alignment: As audited in `docs/prompt-bar-plan/reports/V5.md` (and summarized in `VERDICTS.md` row 2), the "stuck Generate button" issue was verified as PARTIAL—caused by either hung requests or cross-navigation in-memory state retention without submit reconciliation. The combination of registry token tracking, mount reconciliation, and `finally` execution in S4 resolves this lifecycle defect without altering parent `isGenerating` prop precedence (`Boolean(propIsGenerating || storeIsGenerating)`).
